# BudgetGuard 残高ウォッチ（プロトタイプ）

クレジットカード・銀行アプリの「利用通知」を検知して、都度「いくら使ったか／今月あと残り予算はいくらか」を通知するAndroidアプリのプロトタイプです。

要件どおり、検知方法は最小構成（Android通知リスナー）にしつつ、あとから他の検知方法（メール解析、銀行API連携など）を追加しやすい設計にしてあります。

## できること

- 月の予算額と、締め日（何日始まりで「今月」とするか）を設定
- 「監視アプリ選択」画面で、通知を見張りたいクレカ・銀行・QR決済アプリにチェック
- 対象アプリから金額を含む通知が来ると、正規表現で金額（¥1,234 / 1,234円 など）を抽出して記録
- 記録するたびに「支出¥X / 残り予算¥Y」というローカル通知を表示
- ホーム画面で今月の残り予算・使用額・最近の支出一覧を確認
- 「通知ログ」画面で、監視対象アプリから来た通知の生テキストと解析結果（金額を検出できたか）を一覧表示 → 解析精度のチューニングに使う

## ビルド方法（Android Studio）

1. Android Studio（Koala 以降推奨）で本フォルダを「Open」
2. 初回は `gradlew` のラッパーjarをこのプロジェクトには同梱していません（このセッションの実行環境がインターネット制限でGradle公式配布元にアクセスできなかったため）。Android Studioで開けば自動生成・同期されます。うまくいかない場合は、ターミナルでこのフォルダ内で以下を一度実行してください。

   ```
   gradle wrapper --gradle-version 8.7
   ```

3. 通常どおり Run ▶️ で実機（またはエミュレータ）にインストール

  - minSdk 26（Android 8.0）以上が必要です（NotificationListenerServiceのAPI要件）
  - iOSには対応していません。iOSは他アプリの通知を第三者アプリが読み取る仕組みが提供されていないため、同じ方式は実現できません（今後iOS対応する場合は、メール解析やスクリーンショット共有など別方式が必要）

## 初回セットアップ（アプリ内で必要な操作）

1. 起動時に通知権限（Android 13+）のダイアログが出るので許可
2. ホーム画面に「通知アクセスが未許可です」というカードが出るので「設定を開く」→ システム設定でBudgetGuardへの通知アクセスをON
   - この権限だけはシステム設定からの手動操作が必要です（Androidの制約で、アプリ内から直接ON/OFFできません）
3. 「監視アプリ」タブで、実際に使っているクレカ・銀行・QR決済アプリにチェック
   - 主要アプリ（楽天カード、三井住友カード Vpass、PayPay など）はデフォルトでいくつか登録済みですが、パッケージ名は公開情報からの推測を含むため、実機で一覧を確認してご自身のアプリにチェックを入れ直すのが確実です
4. ホーム画面で予算を設定

## アーキテクチャ（拡張しやすさを意識した設計）

```
notification/  … 「支出イベントをどう検知するか」
  SpendingNotificationListenerService … 通知リスナー（現状唯一の検知手段）
  AmountParser / AmountParserRegistry  … 通知テキストから金額を抜き出すロジック（アプリ別に差し替え可能）
  BalanceNotifier                      … 「支出¥X/残り¥Y」通知を出す

data/          … 「検知した支出をどう記録・集計するか」（検知方法に依存しない）
  TransactionIngestor  … あらゆる検知源が書き込む単一の窓口
  BudgetRepository      … UI が唯一話しかける相手（Room + DataStore の詳細を隠蔽）
  Room (Transaction/NotificationLog) / DataStore (予算・締め日・監視アプリ)

ui/            … Jetpack Compose 画面（ホーム / 監視アプリ選択 / 通知ログ）
```

### なぜこの形にしたか（後から拡張する前提）

「ミニマムで作って、後から拡張したい」という要望に対して、検知ロジックと記録ロジックを分離しています。

- 今後「メールの利用明細を解析する」「銀行の残高照会APIと連携する」といった新しい検知方法を足したくなったら、`notification/` と同じ階層に新しいクラスを作り、`TransactionIngestor.ingest(...)` を呼ぶだけで、UI・DB・通知まわりは一切変更不要です。
- 金額の抽出（`AmountParser`）はアプリごとに通知文言が違う（「ご利用のお知らせ」「お支払いが完了しました」など）ため、パッケージ名ごとに別パーサーを登録できる `AmountParserRegistry` にしてあります。実機で「通知ログ」画面を見ながら、検出できていないアプリ用にパーサーを追加していく想定です。

## 既知の制約・注意点（プロトタイプとして）

- **金額の自動抽出は完全ではありません。** 通知の文言はアプリごとに異なり、実機の実データでチューニングが必要です。「通知ログ」画面で生テキストを見ながら `AmountParser.kt` の `AmountParserRegistry` にアプリ別ルールを追加していくのが前提の設計です。
- **通知の重複防止は簡易実装です。** 同じ通知が更新された場合の二重カウントを防ぐ簡易的な仕組みは入れていますが、完全ではありません。
- **QUERY_ALL_PACKAGES 権限を使用しています。** 「監視アプリ選択」画面でインストール済みアプリを一覧するためです。個人利用・サイドロードでは問題ありませんが、Google Playに公開する場合はこの権限の使用理由の申告が必要、または既知のアプリだけを対象にした `<queries>` 宣言への変更が必要です。
- **本セッションの実行環境にはAndroid SDKがなく、実機ビルドの動作確認はできていません。** コードは注意深くレビューしていますが、Android Studioで開いた際に依存バージョンの微調整が必要になる可能性があります。
- 通知チャネルの小さいアイコンは仮のシステムアイコンを使っています（`BalanceNotifier.kt` 内にTODOコメントあり）。
